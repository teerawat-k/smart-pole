# T11 · Sensor archive controller — generic facade ใช้ registry

Epic: E08

## Expected
- `src/modules/sensor-archive/` — facade ที่ใช้ registry — generic endpoint สำหรับ frontend
- Endpoints:
  - `GET /api/sensor-types` — list enabled sensor types (frontend ใช้ render UI)
  - `GET /api/poles/:poleId/sensors/latest` — return latest reading ของทุก sensor type ที่ pole นี้รองรับ (`{ pm25: {...}, temperature: {...}, ... }`)
  - `GET /api/poles/:poleId/sensors/:sensorKey/history?from&to&interval` — generic history (route ไป repo ของ sensor นั้น)
  - `GET /api/poles/:poleId/sensors/:sensorKey/aggregate?from&to&granularity` — generic aggregate
- ภายในใช้ `getSensorHandler(key)` + `getSensorRepository(key)` (registry pattern)
- frontend ใช้ endpoint generic เหล่านี้ — ไม่ต้อง hardcode per sensor

## Test Guide
- [ ] /sensor-types return enabled list
- [ ] /poles/:id/sensors/latest = 3 sensors data
- [ ] /poles/:id/sensors/pm25/history ทำงาน
- [ ] sensor key ไม่มีใน registry → 404
